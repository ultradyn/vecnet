# Claude Delivery Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Automatically register eligible Linux Claude Code root sessions and report their status through the existing Vecnet delivery daemon without changing how Claude receives messages.

**Architecture:** Share the existing per-user daemon lease and watch coordinator with Codex. The CLI owns private binding and setup state; the host observes registrations and publishes a separate versioned status document. Hook/Monitor remains the only automatic Claude delivery path in this slice.

**Tech Stack:** Go CLI and managed runtime, Node 22.18+ TypeScript launcher, existing local state/locking helpers, Node test runner and Go tests.

**Spec:** [Claude Code delivery through the shared Vecnet daemon](../specs/2026-11-19-claude-delivery-design.md) (`60ff9242`). This plan implements slice 1. The later slices have independent verification and release decisions; see the handoff at the end.

## Global Constraints

- Preserve `vecnet-codex-delivery.service`, both existing host entry paths, the exact singleton lock inode, and Codex's strict status v1 schema. Never launch a second daemon for Claude.
- Initial registration candidate: Linux x86-64 with Claude Code 2.1.322 and a verified private endpoint. A passive registration is not native compatibility or readiness to post. Leave untested builds and hosts on legacy; do not identify a runtime by a guessed version or an endpoint alone.
- No Claude inbox writes, native reservations, native reply listeners, acknowledgement, policy changes, token forwarding, or native takeover in this plan. No new Claude watch subscription until there is a consumer with an approved claim contract. Keep existing Hook/Monitor output and Codex scheduling intact.
- Canonical Vecnet config/profile/delegation, verified hub/caller/recipient, canonical Claude config root, session ID, UID, PID, start/boot identity, endpoint and generation are separate fields. No CWD, name, most-recent-session, or borrowed-credential targeting.
- SessionStart registration is bounded, read-only with respect to the hub, and emits no Claude context. Hooks with ambiguous identity, subagent evidence or insufficient root provenance cannot register. Use existing project inventory, recognized hook ownership, runtime installer and repair classes.
- Durable opt-outs are never cleared by enrollment, a hook, or repair. Diagnostics do not contain secrets, peer bodies, socket paths or credentials in arguments. Tests use private homes, fixture credentials and loopback/no provider.

## Review Focus

1. A legacy host dies by SIGKILL leaving readiness files: the replacement can take the original lease, and no stale status is reported as live (Tasks 1 and 5).
2. A principal-wide reader and a recipient-scoped reader at the same URL must not share a notification source; an old credential's final event cannot wake the new epoch (Task 2).
3. Two profile aliases for the same recipient or two roots in the same directory must not silently buy a second binding or steal the first (Task 3).
4. Process reuse, `/clear` in the same process, or registry replacement between validation and commit must not leave an old generation usable (Task 3).
5. Repair after redemption with a replaced profile or changed hook settings must not consume another invitation, adopt a different identity or overwrite unrecognized user hooks (Task 4).

### Task 2: Pool verified Codex notification watches without changing dispatch

**Interfaces:** Create `createWatchPool(deps: WatchPoolDeps): WatchPool` in `delivery/watch-pool.ts`. `WatchScope` is `{hubIdentity: string; endpoint: string; streamOwner: string; credentialSlot: string; scope: string}`; use an explicit scope discriminator, including whether the CLI opens the default stream or a narrowed one. `WatchRequest` is `{scope: WatchScope; revision: string; start: () => WatchChild}`; `WatchChild` is `{close(): void; ended: Promise<WatchEnd>; onEvent(f: (event: WakeEvent) => void): () => void}`; an adapter's `close` must synchronously fence its event callback and request child termination. The pool's `close()` waits for owned children to exit before the host releases the lease. `WakeEvent` is `{priority: 'wake' | 'wake_idle'}` only; `WatchEnd` is `{kind:'reconnect'} | {kind:'terminal'; status:number}`. `WatchPool.subscribe(request: WatchRequest, notify: (event: WakeEvent) => void, stopped: (end: WatchEnd) => void): () => void`; `close(): Promise<void>`. Pass the pool into Codex engine dependencies. Verification may reuse a bounded, profile-scoped CLI check, but must return the *actual* pinned hub identity, caller and stream scope; a former per-binding stream with unproved scope retains an exclusive key until scope is verified.

Use `func (a *app) registerClaudeRoot(ctx context.Context, scope claudeScope, root claudeRoot) (claudeBinding, error)`; `func (a *app) readClaudeBindings() ([]claudeBinding, error)` and `func (a *app) setClaudeOptOut(ctx context.Context, scope claudeScope, disabled bool) error`. Platform files supply `validateClaudeRoot(root claudeRoot) error`; on nonqualified platforms return typed unsupported, no partially trusted binding. Registry and opt-out use one strict v1 private document `claude-bindings.json` via `lockLocalState(ctx,"claude-bindings")` and current private atomic writers. Keep the coordinate checks reusable without a socket write. Expose a read-only redacted snapshot to the host via a versioned `claude runtime-snapshot` CLI child; include generation and opaque local binding key, not raw socket/auth data. No host-side parsing of the full registry is required.

## Follow-on plans and boundaries

Each follow-on has a working independent deliverable and needs its own reviewed execution plan. **Passing this plan is not a release approval for any follow-on.**

| Follow-on | Spec surface, deliverable, and explicit stop |
| --- | --- |
| **Claims and fence; fake transport only** | Canonical recipient claim journal and writer guards across `hook.go`, Monitor display/ack (`watch.go`) and `inbox_display.go`. One authoritative `reserved → attempting → uncertain` flow; one in flight and cap 128 per scope; immutable attempt/tombstone and explicit `deliveries`/`resolve`. No native auto-ack. Re-run order-barrier, definite-release, crash, duplicate ID, exact-generation and actual old/new binary coexistence tests in both host modes. Native stays off. |
| **Linux pointer experiment** | Implement only the qualified fixed `Vecnet` pointer with validated hub thread/message IDs; cap 4 KiB encoded, one second connect/write. Place verified connect and write in one bounded Go helper under the writer guard. Preserve ambiguity after possible write, no replay/fallback, no cursor advance. Test endpoint/owner/lifecycle, expected request envelopes and default policy against disposable Claude; exact test build only and explicit experimental opt-in. Keep disabled if the default reply hint is misleading or the hot path cannot be qualified. |
| **Default `wake` and optional data modes** | Require proof of writer takeover/rollback, uninterrupted operator access to pending work and a sustainable bounded recovery window, actual request framing and policy checks.

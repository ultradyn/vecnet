> **Amendment / CoS ruling 2026-11-07:** simplify ownership to one runner process holding the lifetime flock: Go acquires it and execs Node with the lease FD inherited. **Goal:** the next vecnet action registers an eligible existing Codex session and ensures one durable delivery owner per hub, including after upgrades.
**Architecture:** Go resolves identities, maintains bindings and acquires a per-hub process lease before execing the credential-free Node runner in the same process. The runner reuses the existing gated Codex RPC and delivery engine. Stable on-disk state and ordered owner replacement preserve the existing claim/receipt recovery protocol.
**Tech Stack:** existing Go 1.26+ module; Node >=22.18 TypeScript stripping and `node:sqlite`; no new runtime packages.
**Spec:** incoming brief `.scratch/vecnet/handover/codex-cos-brief.md` section 3; existing app-server plan Global Constraints, with automatic consent replacing manual opt-in only; PROTOCOL sections 2.3, 5.2, 13.9.
**Exit tests owned:** ET1 next-action registration; ET2 one owner/hub under races and crashes; ET3 hooks/app-server receipt once; ET4 binary/launcher replacement preserves recovery; ET5 two sessions on one hub and one session on two hubs; ET6 durable opt-out and fallback.

## Review Focus

1. Two simultaneous ensure calls and runner crashes -> at most one sender retains the inherited lease. Pinned in Task 2 (`TestCodexDeliveryConcurrentEnsure`, `TestCodexDeliveryWorkerCrash`).
2. An accepted send loses its response across a binary/launcher replacement -> history settles the original clientId without another injection. Pinned in Task 5 (`automatic delivery recovers an ambiguous send across replacement`).
3. Unbind followed by another CLI/hook action -> opt-out remains; missing socket and live foreign thread leave hooks/inbox available. Pinned in Task 3 (`TestCodexAutoOptOut`, `TestCodexAutoFallback`, `TestCodexAutoDoesNotSteal`).
4. Two hub owners share one canonical home -> combined admission never treats each hub as eight slots, and hub/caller pins cannot cross-route. Pinned in Task 1 (`hub filtering follows shared home admission`, `two hubs never claim each other's bindings`).
5. Hung probe, missing Node or missing runner assets -> under about 200 ms added latency with the original command/hook result intact. Pinned in Task 3 (`TestCodexAutoBoundedCost`).

## Decisions the plan makes

Context: existing launcher startup requires a credential and starts unrelated jobs; normal CLI users need delivery without configuring a launcher job service.

| Idea | All | No launcher bearer | One owner per hub | Reuse existing engine |
|---|:---:|:---:|:---:|:---:|
| Enable ordinary launcher as-is | no | no | no | yes |
| Rewrite delivery in Go | no | yes | yes | no |
| Delivery-only Node runner execed under inherited flock | yes | yes | yes | yes |

The ordinary launcher reads a bearer and has no per-hub fence. A rewrite discards the tested RPC/receipt state machine. Choose the separate runner. A dedicated systemd template gives unattended restart after installation; a detached runner uses the same lease, with recovery on the next vecnet action after process loss.

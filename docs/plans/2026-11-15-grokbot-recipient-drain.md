## Small durable state and interfaces
- Provisional migration `0039_grokbot_recipient_drain.sql` adds capability, `grokbot_wakes`, `grokbot_covers`, indexes, and nullable unique `route_runs.grok_wake_token`. Existing route_runs callers/rows keep null tokens. Do not modify prior migration checksums or backfill historical coverage.
- `grokbot_wakes` primary key `(route_id,recipient)` stores representative ID, fresh lease token, phase claimed/armed/waiting/covered, lease deadline, frozen PendingCount, retry deadline/failure ordinal, cover deadline, idle counter/captured counter and `cover_valid` marker. No observed-invocation flag or replacement attempt definition. Representative/route references must not pin history or cascade away an armed gate.
- `grokbot_covers` primary key `(route_id,delivery_id)` stores recipient and first-covered time; FK delivery DELETE CASCADE, no route FK. Historical attribution survives route changes until delivery collection; repeated coverage is idempotent. Coverage is side metadata, never a new Delivery state or receipt.
- Add optional `DueDelivery.GrokWake *GrokWakeClaim`, containing `Token string` and `PendingCount int`. ClaimDue's signature and attempt increment remain unchanged; only opted-in leaders are returned. Followers stay queued/held as before, attempt=0 and attempts_left unchanged.
- New `BeginGrokbotPOST(ctx context.Context, d DueDelivery, now time.Time) (bool,time.Duration,error)` validates token/lease/current delivery and authority, expected URL/capability and shared budgets in one writer transaction. One claimed→armed transition reserves a unique run token and captures the CURRENT idle counter; false spends no run and routes through existing DeferPush compensation plus a domain deadline.
- New `GrokbotWakePushResult(ctx context.Context, d DueDelivery, status int, body []byte, retryAfter time.Duration, netErr error, now time.Time) error` settles the opted-in token and normal representative outcome atomically. Preserve existing `GrokbotPushResult` wrapper/signature for legacy callers; worker chooses the matching path in the same task.
- Release opted-in refused/noninvoked reservations by `(route_id,grok_wake_token=d.GrokWake.Token)`, never timestamp or reusable rowid alone. Old invocation identity remains in its own route_runs row even when coordinator token changes; a stale non-200 may release only its own token, never the replacement reservation. The legacy `ReleaseGrokbotRun` keeps its public API and one-null-row timestamp semantics, but its candidate selector MUST include `grok_wake_token IS NULL` as well as route/time. Thus neither release path can select the other population. Budget counts/pruning include BOTH token and null reservations; preserve existing expiry/prune/removal rules, and removal does not erase reservations.
- Keep representative claim-attempt and existing shutdown behavior. Budget denial and no-client preflight use DeferPush compensation where the claim is still current; held/covered followers reserve no run. Attempted telemetry still means actual payload-client invocation, not proven remote execution; Step counts claimed representatives, so receiver/client counters are the POST oracle.

## Transition table (all coordinator updates transactional)
| Event | Delivery/receipt/budget | Domain gate and next eligibility |
|---|---|---|
| Due drain-v1 work, no gate | Claim oldest due unheld unexpired representative using existing attempt semantics; annotate followers without receipts | Elect one fresh token under BEGIN IMMEDIATE, lease=PushLease; SQL-cover other pending wake/wake_idle in the domain, including later same-thread rows, with current elected representative ID explicitly excluded |
| New wake during claim/I/O/success cover | Leave it inbox-visible and unreceipted; no follower attempt/run | Attach follower coverage excluding the current elected/armed representative ID, without sliding lease/cover/retry deadline; preserve held flags |
| Begin after idle BEFORE Begin | Validate current URL, mode, peer enabled/current principal and route owner; reserve only this invocation | Capture idle counter NOW and set cover_valid=true; earlier idle does not suppress the new run's future window |
| Idle AFTER Begin | No withdrawal of I/O or fabricated receipt | Increment counter, close successful cover, retain active lease; late 200 cannot reopen cover |
| URL A→B→A, capability/key or principal/disable change AFTER Begin | Already dispatched request may finish under existing contract; its budget identity remains its own | Set cover_valid=false and clear cover transactionally; restoring A/authority does not restore marker. Keep original lease, no overlapping new invocation |
| Classified started 200, valid current token/counters/marker | Normal representative accepted receipt unless already advanced by ack/receipt; keep run reservation | Open cover until settlement+10m; settle group independently of stale representative receipt state |
| Started 200, invalidated same token | Existing representative outcome may settle; no new-domain receipt/coverage or reservation transfer | Do not open/slide any window, reset repaired state or extend deadlines; retain original exclusion until its lease deadline, then re-elect current eligible work |
| Retryable 400/408/429/5xx | Existing representative retry/attempt decrement/exhaustion and classification; release exact refused run | Advance failure ordinal to max(previous+1, representative attempt); shared deadline = now+PushBackoff(ordinal,RetryAfter). Followers/new arrivals cannot bypass it |
| Payload terminal 400, terminal 200, auth/disabled refusal, exhausted leader | Dead-letter only representative with existing alert behavior; followers unreceipted. Non-200 returns reservation; terminal 200 keeps today's reservation semantics | Advance the same ordinal/deadline (never reset on leader replacement); no permanent endpoint/domain block or new operator recovery endpoint |
| Network ambiguity/cancellation after client invocation | Preserve current shutdown/lease semantics and conservative reservation; Attempted telemetry remains separate | Gate until max(original lease deadline, applicable retry deadline). Restart/late-token results cannot replace current gate or reopen cover |
| Key/body/request preflight false, budget denied | Zero client observation/run; compensate claim through DeferPush (existing claim evidence remains honestly documented) | Persist group preflight backoff or budget wait/error delay; no per-poll follower rotation. Advance the group ordinal for preflight failure, not budget denial; cadence only, not delivery attempt persistence |
| Successful cover expires or explicit idle after settled success | If all work handled/expired, no POST; otherwise pick one remaining wake | One fresh coalesced push, not one per follower; accepted old leader need not be re-POSTed |
| Leader handled/expired/discarded/collected | Never revive it or invent a receipt; choose oldest remaining valid work with a NEW frozen count/body | Preserve shared deadline/ordinal through replacement; removal of the old row cannot clear a still-active gate; a valid later arrival becomes eligible after that finite deadline |
| Repair/explicit retry/removal/re-enable | Preserve existing endpoint operations and rolling budget; no new recovery API | URL/key repair or explicit retry may reset failure cadence when no armed gate; while armed only invalidate old cover rights. Removal prevents Begin and invalidates cover, retaining lease tombstone; re-enable never restores an old marker |

- Known preflight errors are caught before reservation/client entry. If cancellation lands after reservation but before a proven client entry, release only when noninvocation is known; an interruption/crash between those boundaries is ambiguous and retains its own reservation/lease. Do not promise exact no-POST billing across a crash.
- Before-Begin URL/mode/authority changes cancel the unarmed token and compensate its claim; re-claim current data. After-Begin mutation invalidates the right to cover, not the active lease. This covers principal moves under an unchanged peer route, disable→enable, mode revoke→enable and URL A→B→A.
- OnIdle still releases holds for explicit idle or stale unknown; only SetPresence's explicit-idle transaction changes the idle counter. Valid success resets failure cadence; stale/invalidated success cannot reset a new token's/repaired state. Once a retained invalidated lease expires, current mode/authority/held/TTL/handled checks determine eligibility anew.
- Handled means processed or recipient-including ack acceptance, not read and not an accepted run-start alone. Applicable ack scopes are peer/*, current-principal/peer and current-principal/*, never another narrowed peer or former principal. Annotate known no-POST handling (untouched followers or an unarmed claimed token), excluding armed/ambiguous representatives and accepted run-starts even if telemetry is missing. A genuinely handled unarmed leader before Begin may be annotated through this separate handling path, idempotently. Bulk election/attachment never creates its coverage solely because it was elected; preserve earlier legitimate coverage if a follower later becomes leader. No duplicate receipt, read/no-op annotation or historical reconstruction.
- Atomic Begin is the no-withdrawal boundary: ack/processed before it suppresses POST; a later receipt cannot retract an invoked request or release its group lease. A non-current token cannot mutate current delivery/group state. Settling the same token twice is a no-op; serialized group settlement and representative state/attempt guards must prevent a second decrement, receipt or cover extension. Physical exactly-once across DB/network crashes is unavailable; conservatively retained reservations are not proof of remote billing.

## Query shape, continuation and cleanup
- Add partial pending domain index `deliveries(route_id,recipient,event_seq)` for queued/pushed wake/wake_idle, covering state/held/expires_at as useful; partial due index `deliveries(next_attempt_at,event_seq,route_id,recipient)` for unheld pending wakes; coverage index `(route_id,first_covered_at,delivery_id)` and coordinator indexes on gate deadlines. Preserve legacy query/index paths.
- Candidate discovery uses keyset pages `(event_seq,dly_id)` with existing ClaimBatch-sized working memory, joins domain gates by primary key, and continues after coverage-only/gated/handled pages until representative limit or exhaustion. Do not return attachment-only empty work while a later domain is eligible; do not enumerate/materialize every active domain or all follower IDs in Go.
- PendingCount uses SQL COUNT(*) over exact domain/state/priority/expiry predicates INCLUDING the leader. Bulk coverage/attachment uses INSERT..SELECT over that base population PLUS `(:representative_id IS NULL OR d.dly_id <> :representative_id)`, bound to the current elected/armed representative. Conflict-do-nothing preserves first-covered evidence, including a formerly covered follower now elected leader; never delete/rewrite that evidence. No member IDs/payloads are materialized.
- Candidate anti-joins skip already annotated followers under active gates; inactive/expired-gate covered rows are eligible again. Held arrivals may be annotated through coverage-only discovery without making them pushable. Representative exclusion leaves existing indexes/keyset continuation, exact count and bounded-memory query shape unchanged.
- Preserve the existing earlier-pushable `(recipient,thread)` predicate for actual representative selection, including earlier work on another route; grouping followers inside the elected domain does not authorize a later POST to overtake it. Inbox reads retain event order.
- Close candidate iterators before hydrating only elected representatives on the same transaction/connection. SQL exact counts/set operations can do O(n) work and writer-lock time; bounded memory is not a hard transaction-time, delivery, work or storage bound. No arbitrary global scan cap that changes eligibility/count accuracy.
- Cleanup coordinator only when no active claimed/armed/cover/retry gate remains AND no relevant retained pending wake/wake_idle exists for that exact domain (held included). Terminal/collected leaders do not pin it; pending followers do. Preserve an empty active gate so a new arrival cannot evade cadence; after gate expiry and no relevant work deletion is safe. Coverage FK cleanup adds no history retention pin.

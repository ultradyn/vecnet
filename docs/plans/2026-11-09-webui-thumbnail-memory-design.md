## Decision and logical limits
- Goals: G1 bound aggregate application-owned compressed thumbnail work across mounts in one document; G2 offscreen registrations create no automatic requests/src; G3 preserve history, viewer interaction, original downloads, anchors and receipts with explicit pressure/wait states.
- Concurrency alone does not bound resident bytes; loading=lazy alone still fetches eagerly; lowering history caps loses access; omitting images loses functionality. Select demand leases plus shared admission and local payload ownership. G3's successful viewer load requires actual transport settlement and a valid eligible response.
- Controller provisionally accepts synthetic proposals B=32 MiB, C=2 running requests, E=16 running/resident payload entries, N=16 source permits, Q=16 queued hash jobs; retain M=10 MiB/image. Tiny injected limits are allowed for future tests; these are not measured shipping optima.
- Across all caches using the document owner: residentBytes + M×running <= B; running <= C; running+resident entries <= E; queued jobs <= Q; reserved-or-attached source permits <= N. Each physical src-bearing image requires its own permit, including viewer and redraw handoffs; duplicate hashes do not bypass N.
- Reserve M before dispatch regardless of declared length. One running entry/reservation persists through fetch, body reads and requested cancellation cleanup until actual settlement; success converts it atomically to validated Blob.size, failure/cancellation releases it exactly once. Zero-byte results still consume E.
- B bounds logical compressed payload/reservation ownership, not whole-tab RAM. Stream-delivered chunks, Blob copies, bounded JSON parsing, network buffers, native decode/animation/browser caches and independent tabs are outside that byte equation; instrument transient/native effects separately.
- Registrations may hold metadata/node references proportional to current loaded DOM. Active demand owners require N permits even while waiting/loading; queued jobs are <=Q and retired running records <=C. No all-history promise queue, permanent failure registry, mount-history registry or retained diagnostic arrays.

## I1 / R-M31 — document-lifetime budget, mount-local payloads
- Add pure `internal/ui/static/thumbs-budget.js`, exporting `createThumbBudget({limits})`. thumbs.js creates one module-lifetime default budget, reused by every createThumbs/mount in that app document; tests inject one budget into multiple real caches. No reset on route change/sign-out, no app.js edit and no shared payload cache.
- Budget interface: `enqueue({key, priority, onStart, onCancel}) -> ticket|null`, `claimSource(ownerKey, {onCapacity}) -> permit|null`, read-only scalar `stats`. Keys include cache identity+hash+task generation; source keys include cache+occurrence/viewer identity. No SHA-only global sharing; capacity callbacks are coalesced and held only by <=N permits, not a separate subscriber registry.
- Ticket interface: `setPriority(priority)`, `cancel()`, `settle({residentBytes})`, `dropPayload()`. onStart(ticket) fires once only after C/B/E reservation; cache must settle exactly once after its complete API/cleanup task ends. A cancelled ticket cannot convert to resident bytes. Source permit `drop()` is idempotent and follows physical src detachment; `move(nextOwnerKey,{onCapacity})` transfers one detached permit without incrementing N or retaining its old callback.
- Queued cancellation removes the ticket immediately; once-only onCancel(reason) lets cache suppress displaced automatic owners, drop their source permits and clear pending entries. For running cancellation it requests abort through cache, then clears callbacks, but keeps C/M/E until settlement; cache release cannot decrement/reset it. Resident release detaches consumers, revokes the local URL, then drops payload accounting. No force-free/timeout/Promise.race path for stalled work.
- Shared owner stores only bounded tickets/source permits and scalar counters, never Blob/Response/URL/DOM. Start callbacks are discarded after dispatch; cancelled records clear owner notifications and mount callbacks. Release clears local registries/listeners/closures so <=C retired task records cannot retain old DOM or an accumulating list of mounts.
- No budget-wide reset/release API. Each mount cancels its own queued/running tickets and drops its resident/source permits; an old task's terminal callback addresses only its original ticket and cannot alter successor counters, URL or DOM. Remounts under C stalled retired calls must admit zero replacement requests.
- Shared queue selects explicit viewer work FIFO by explicit acceptance/upgrade order ahead of queued automatic work; new automatic work cannot displace accepted explicit jobs. At Q, explicit work may cancel a queued automatic ticket, never a running reservation or earlier explicit ticket. Otherwise reject admission with a retryable visible state and retain no pending callback. Deliver notifications after accounting mutations; callback reentry must preserve all invariants.
- Source permits bound active occurrence/viewer leases, including pending viewers. Unadmitted boxes retain registration/status only; no per-box capacity subscription. One coalesced demand pass per permitted instance runs on actual capacity/visibility changes; instances denied all permits wait for external demand events/explicit retry rather than building a global wait list.

## I2 / R-M32 — opt-in bounded transport and error precedence
- New hub-only `api.thumbnailBlob(sha, {signal, maxBytes}) -> Promise<Blob>`; validate integer 0<maxBytes<=M. Add a private thumbnail-only bounded response branch before generic 204/blob/JSON handling; preserve existing blob(sha,id), R2 download, avatar and ordinary JSON behavior.
- Preserve authenticated same-origin SHA path, bearer header, no-store, omit credentials and passed signal. Success accepts only current raster allowlist, both header/final Blob type, and <=maxBytes actual bytes; no URL here. A 204/missing image body is not a valid image result.
- Content-Length is only an early oversized-body rejection hint. Stream success chunks under maxBytes; test actual accumulated bytes and reject before retaining an overflowing chunk. Retain bounded owned views/copies without oversized backing buffers; avoid extra contiguous success copies and discard chunks on every exit. Never use response.json/text/blob/arrayBuffer or an unbounded fallback in this opt-in branch.
- For every non-2xx status, read at most K=min(8 KiB,maxBytes) bytes within the existing M reservation, regardless of Content-Length/media type. Complete bounded bytes may be UTF-8 decoded/JSON.parsed; accept only an object error envelope with optional string code/message and object non-array details. Ignore unrelated fields; malformed shape/encoding/JSON is no envelope.
- Preserve bounded valid envelope code/message/details through existing httpError. Overflow, absent/unsupported body, malformed or unreadable non-abort envelope uses `httpError(status,statusText,null,Retry-After)`, retaining HTTP status and existing Retry-After normalization. A known HTTP error takes precedence over media/capability/network body errors, except explicit abort.
- On confirmed 401 headers invoke existing once-per-client unauthorized normalization immediately with a generic bounded HTTP error, before any body read or await. Do not wait for a stalled envelope to sign out. Recheck signal afterwards: synchronous sign-out/release may abort and must enter cancellation cleanup. If reading completes, caller receives the bounded detailed 401 error without another callback; header notification may be generic while the final error is detailed.
- A caller abort observed before terminal result selects APIError(0,aborted), even after error headers; a prior confirmed 401 notification remains once-only. AbortError from fetch/read is also aborted; non-abort success read failure is APIError(0,network). Cleanup errors never replace the selected overflow/type/HTTP/abort cause; no automatic retry.
- Abort/overflow/invalid success media/early oversized length/read failure requests body/reader cancellation once, immediately discards retained chunks and removes abort handlers in final cleanup. Observe cancellation rejection, wait for outstanding fetch/read/cancel operations to settle, then release the reader lock in finally and settle the API task. Successful EOF needs lock release, not cancellation.
- Do not race a stuck cancellation/read to an early terminal API promise: its request slot/reservation stays owned. Cleanup can stall forever under ignored abort, but <=C such tasks retain bounded logical reservations. Native stream buffers/oversized delivered chunk allocations are not claimed bounded by this reader.
- Baseline is current evergreen browsers with readable Response.body/getReader, AbortController and IntersectionObserver (plus existing dialog/Blob facilities). Unsupported thumbnail streaming refuses success with an explicit capability error; a known non-2xx still normalizes status with a null envelope. Missing capabilities expose unsupported-viewer text plus Files, with no claim of equivalent viewer support on an included unsupported browser.
- Actual tested browser/version and cancellation timing remain unknown until the parent's Chromium gate. Finite byte caps do not bound time: incomplete <=K error bodies may stay pending; 401 still notifies at headers, 503 waits/cancels under the same bounded accounting.

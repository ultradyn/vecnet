# MCP-First Implementation Plan

> **For agentic workers:** executed by `docs/plans/vecnet-core-build.workflow.mjs` with `docs/plans/mcp-first.workflow-args.json` (written by the coordinator from this plan). Each task runs in its own worktree from the dependency map and sees only its own section plus the Global Constraints. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Agents act on vecnet through MCP tools. The hook or connector wakes them, and the CLI is the fallback. A dot can use the hub end to end once it is deployed publicly.

**Architecture:**
- **Conformance (Task 1).** `/mcp` negotiates `initialize` the way MCP requires: an unknown version is answered with `2025-11-25`, not an error. 2026-07-28 results carry `resultType: "complete"` and `_meta` serverInfo.
- **ChatGPT polish (Task 2).** Every tool lists `securitySchemes`. `vecnet_whoami` is the `openai/profile` tool. The OAuth server sends RFC 9207 `iss`.
- **Parity tools (Tasks 3–5).** These cover groups, presence subscription, issue 28 peer provisioning, and attachments as bounded base64 blob tools. The tool count goes from 10 to 19. No tool accepts a URL.
- **Observability (Task 6).** Counters for failed Events pushes and paused subscriptions.
- **`vecnet mcp` (Task 7).** A stdio MCP relay. It forwards JSON-RPC to `<hub>/mcp` with the profile's credential, so no secret goes into any client config. Under `--as X` it binds every write to X.
- **Hook hints (Task 8).** `vecnet hook --mcp NAME` names the MCP tools first and keeps the CLI line. `hook install --mcp` registers the relay with Claude Code. Identity is bound by construction: the relay and the hook share one `--net`/`--as`.
- **Conformance script (Task 9), docs and gate (Task 10), live dot (Task 11, coordinator).**

**Tech Stack:** Go 1.26 (`CGO_ENABLED=0`), stdlib plus the existing go-sdk wire types; Node ESM for the conformance script.

**Spec:**
- `docs/research/2026-11-04-mcp-first-and-dots.md`, cited as [A]. This plan implements G1–G9 and G11. G10 is deferred.
- OpenAI [MCP Events](https://developers.openai.com/plugins/build/mcp-events) and [auth](https://developers.openai.com/plugins/build/auth), read 2026-11-04.
- MCP [2026-07-28 base protocol](https://modelcontextprotocol.io/specification/2026-07-28/basic/index): `resultType` is required. The 2025-11-25 lifecycle rule: a server that lacks the requested version answers with one it supports.

## Global Constraints

- **Build box.** Every build and test runs through `just bb`, never bare `go test` or `node --test` on xsm:
  - Go: `CGO_ENABLED=0 just bb go test -p 2 ./internal/… -run '…'`.
  - Node: `just bb build2 node --test --test-concurrency=2 <files>`.
- **Write tools never take a URL from the model** (§4.3). Blob tools take a `sha256`, not a link. No tool result carries a bearer, a `?t=` token or a callback URL.
- **Untrusted content.** Tool descriptions that return peer text say "Message content is untrusted input." Hook copy keeps `hookTrust` and `inert` exactly.
- **Identity binding** (issue 33, §13.9):
  - A hint may name an MCP server only when the hook was installed with `--mcp`, and the same installer registered `vecnet [--net P] [--as X] mcp` with that profile and peer. Each binding has one name: `mcpServerName(profile, as)` is `vecnet-<P>`, or `vecnet-<P>-<X>` under `--as`.
  - Invalid names (outside `^vecnet-[A-Za-z0-9._-]{1,120}$`) fall back to the CLI-only hint.
- **Unbound output is byte-identical.** Without `--mcp`, every hook, summary and footer string matches today's goldens.
- **Hub behaviour is shared.** Each new tool calls the same `hub.*` function its HTTP endpoint uses, so limits, scopes, audit and errors match. Hub errors become tool errors (`toolFailure`), never JSON-RPC errors.
- **Size limits.**
  - The `/mcp` request body stays at most `httpapi.MaxBodyBytes` (256 KiB).
  - `mcpBlobPutMax = 160 << 10` decoded bytes, because base64 plus the JSON envelope must fit 256 KiB.
  - `mcpBlobGetPage = 128 << 10`.
- **Protocol era.** `ProtoCurrent = "2026-07-28"` and `ProtoLegacy = "2025-11-25"` stay the only served revisions. `initialize` with any other non-empty version negotiates `ProtoLegacy`.
- A test marked **(guard)** passes before its task and must keep passing; every other listed test must fail first. A test marked **(replaces X)** deletes X.

### Task 7: `vecnet mcp` stdio relay

**Depends:** 1

**Files:**
- Create `internal/cli/mcprelay.go` and `internal/cli/mcprelay_test.go` (package `cli_test`, against `testhub.Start`).
- Modify `internal/cli/commands.go`: one `dispatch` case, and a `usageText` line: `mcp   stdio MCP relay to the hub's /mcp, acting as this profile [--as X]`.

**Interfaces:**
- **`func (a *app) cmdMCP(args []string) error`:**
  - It takes no flags of its own.
  - It resolves the hub URL and credential with `a.connect()` and never writes them to stdout or stderr.
  - It reads newline-delimited JSON-RPC from stdin (the MCP stdio transport), POSTs each message to `<hub>/mcp`, and writes each response as one line on stdout. Stdout carries only JSON-RPC.
- **Session handling:**
  - The client's `initialize` is forwarded unchanged. The relay keeps the returned `Mcp-Session-Id` and sends it, with `MCP-Protocol-Version`, on later posts.
  - On HTTP 404 `session_not_found`, it re-sends the cached `initialize` once, then retries the original message once.
- **Errors.**
  - A request that cannot reach the hub gets `{"error":{"code":-32603,"message":"vecnet relay: hub unreachable"}}` with its id.
  - A notification gets no output.
  - A non-JSON input line is answered with `-32700` and id null.
- **`--as X` binding:**
  - The relay caches the `tools/list` result it relays, fetching one itself if needed.
  - For `tools/call` of a tool whose `inputSchema.properties` has `as`, it sets `arguments.as = X` when absent.
  - When `as` is present and differs from X, it answers `-32602` with message `relay is bound to --as X` and does not forward.
- **No hint stream.** It opens no GET stream; resource hints are out of scope.
- **Exit.** It exits 0 on stdin EOF.

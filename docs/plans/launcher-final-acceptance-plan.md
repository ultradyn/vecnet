### Approved artifact/runtime manifest

Generate this public JSON manifest only after the final build and scoped source reviews. Record and approve its own SHA-256 with the build inventory. The smoke verifies it before any launch; filenames, marker replies, executable access and a protocol handshake alone do not establish provenance. Required common fields:

- `source_revision`: full immutable combined Git HEAD, verified against the selected source checkout.
- `snapshot_sha256`: complete launcher/hub-client runtime asset inventory digest using the installer framing (`name-byte-length:name:content-byte-length:content`, sorted by path). Verify both source assets and actual installed snapshot; the snapshot directory/entry must agree with the install plan.
- `cli_sha256` and `demo_sha256`: digests of the exact selected CLI and demo bytes.
- Native `native`: `executable`, `executable_sha256`, and approved `version`. The controller inventories the running daemon's actual executable; the smoke rehashes those bytes and records the actual supported RPC version, requiring it to equal approval. RPC version/route reporting does not independently attest the daemon's process executable path.
- ACP `acp`: approved `executable` wrapper and `executable_sha256`; `package_json` pointing at the nested `node_modules/@agentclientprotocol/claude-agent-acp/package.json`, `package_name` and `package_version` (`0.101.0`); actual adapter `entry` and `entry_sha256`; fixed `node_executable` and `node_sha256`; expected `agent_name`, `agent_version` and `protocol_version` (`1`). Rehash wrapper, entry and Node, verify the nested package version, and require the actual initialize response to match the approved protocol/agent identity. The top-level bootstrap workspace package is not adapter identity.

The receipt binds source revision, snapshot path/digest, CLI/demo digests, approval digest, actual daemon/adapter version and available effective route metadata. ACP's protocol/session reference does **not attest effective provider/model/effort**: record explicit nulls and an attestation limit rather than inventing values or omitting fields. Successful initial/follow-up model turns and consumed receipt record provider availability observed in that run; they do not prove a particular effective model/provider. Actual provider availability remains a live gate, never a conclusion from synthetic tests or source review. ACP initialization probes only the approved executable's handshake and must finish normally; no session or model turn is created by that preflight.

Native no-rollout/policy-refusal cleanup has separate synthetic launcher/restart/sweep evidence; historical zero-input daemon archive refusals are not silently treated as disappearance or a successful cleanup. Local `withDemo` proves no Fly acceptance or disposable-peer disablement. R-L11 Fly acceptance remains the separate disposable sender+launcher flow below; main owns its additional Fly harness/plan details after this handoff.

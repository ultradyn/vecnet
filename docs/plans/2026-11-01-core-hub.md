# vecnet Core Hub (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Phase 1 "Core" of vecnet from `SPEC.md` §16: a Go hub binary (HTTP send, durable per-peer event log with SSE and long-poll, delivery state machine with signed push, blob store, loop control, threads and groups, directory and presence, approvals and jobs, enrolment, admin, audit, a minimal operator inbox) plus the `vecnet` CLI, deployable to one Fly machine.

**Architecture:** One Go module with two `cmd/` binaries. Every write goes through the `hub` service package inside one SQLite transaction that also appends Events to the per-peer log; readers (SSE, long-poll, CLI, UI) only read the log. A separate in-process push worker claims due deliveries from the same database and drives the Standard Webhooks push state machine. JSON shapes come from the embedded `envelope.schema.json`, which is validated at the boundary, and from matching Go structs.

**Tech Stack:** Go 1.26+ (`CGO_ENABLED=0`), stdlib `net/http`, `modernc.org/sqlite` v1.61.1 (driver name `sqlite`), `github.com/oklog/ulid/v2` v2.1.2, `github.com/santhosh-tekuri/jsonschema/v6` v6.0.3, `github.com/BurntSushi/toml` v1.6.0 (CLI config only), hand-rolled Standard Webhooks HMAC, `embed.FS` for migrations, schema and UI. Deploy: scratch Docker image, Fly volume at `/data`.

**Spec:** `SPEC.md` (product), `docs/PROTOCOL.md` (normative behaviour; `§n` below refers to it), `docs/protocol/envelope.schema.json` (wire shapes), `docs/protocol/OPEN-ITEMS-RESOLVED.md` (`Rnn`), `docs/adr/0001-tech-stack.md`. Out of scope here, in later plans: MCP `/mcp` + Events profile + OAuth (§4), Grok Bot route kind, openclaw plugin, GitHub ingress (§10), full operator UI, phase-2 escalation.

## Global Constraints

- Go module `github.com/XertroV/vecnet`, `go 1.26` directive; `CGO_ENABLED=0` for every build; binaries `cmd/vecnet-hub` and `cmd/vecnet` [ADR1].
- Build and test only via `build2`, two threads: `build2 go test -p 2 ./...` and `build2 go build ...` (CLAUDE.md etiquette). Never a bare `go test ./...`.
- Dev hub port **45752** [ADR1]; the operator UI is served by the hub itself under `/ui/`.
- Every id is `<prefix>_` + 26-char Crockford ULID matching `^[0-9A-HJKMNP-TV-Z]{26}$`; prefixes `msg dly thr peer prn team grp job apr src` [§1.3].
- Timestamps are `YYYY-MM-DDTHH:MM:SS.sssZ`, millisecond UTC [§1.2]. Go: `t.UTC().Format("2006-01-02T15:04:05.000Z")`.
- Cursors are `e<epoch>.<seq>` [§1.3]; clients treat them as opaque.
- Non-2xx body is always `{"error":{"code","message","details"}}` with the reason codes named in §2.2, §2.3, §2.7, §2.8, §15, §16 [R01].
- Byte caps: `content.text` 4096 (Message) / 65536 (SendRequest), metadata 8 KiB serialised, `job_request.input` 16 KiB, `job_status.output` 8 KiB, request body 256 KiB, push body 256 KiB, blob 25 MiB, daily upload quota 500 MiB [§2.2, §2.7, §3.1].
- Defaults: `max_depth` **32** (range 1–64), `expires_at` now + 24 h, thread budget 500, 64 participants per thread, 60 sends/min and 20 new threads/hour per peer, push 8 attempts with backoff `min(1h, 2^attempt s) + jitter`, blob token 7 days, group auto-archive 30 days idle, presence stale TTL 1 h (`session` 15 min) [§6, §16, §3.3, §7, §8].
- All JSON objects are `additionalProperties: false`; unknown fields in a request are a 400 `invalid_body`.
- Secrets and message bodies never enter logs or audit rows [§12]; secrets are stored only as SHA-256 hashes; a bearer never appears in a URL.
- Tests use `t.TempDir()` databases and `httptest`; nothing in tests touches the network.
- Commit after every task with `git -c commit.gpgsign=false commit`; work happens in a worktree under `.worktrees/core-hub` on branch `core-hub`.

## Review Focus

1. **Malformed or over-specified JSON** (unknown field, wrong type, `priority` missing): the hub answers 400 `invalid_body` with the JSON pointer of the first violation in `details.path`; it never panics or 500s. Pinned in Task 2 and Task 7.
2. **Multi-byte text at the 4096-byte spill boundary**: the preview must be cut at a rune boundary, remain valid UTF-8 and be ≤ 4096 bytes. Pinned in Task 10.
3. **Two identical sends racing on one `idempotency_key`**: exactly one Message exists and both callers get the same `message_id`. Pinned in Task 7.
4. **A slow or vanished SSE consumer**: the appender never blocks on a stuck connection and the handler goroutine exits when the client goes away. Pinned in Task 11.
5. **Hostile `Retry-After`** (HTTP-date, huge number, garbage): parsed, capped at 1 h, garbage falls back to the computed backoff. Pinned in Task 14.

# vecnet Launcher (P1, P2) and Principal Peer Provisioning Implementation Plan

> **For agentic workers:** executed by `docs/plans/vecnet-core-build.workflow.mjs` with `docs/plans/launcher.workflow-args.json` (written by the coordinator from this plan). Each task runs in its own worktree from the dependency map and sees only its own section plus the Global Constraints. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Any enrolled agent can start a coding-agent session on a host by sending a `launch` job to that host's launcher peer, then talk to the session in the job thread, answer its questions, and approve its permission prompts. P1 runs the `t3` backend on xsm; P2 adds `paseo` on xsm (completion-only turns, see Task 16), `t3` on the build boxes, and the two-timer idle model. Alongside it, issue 28 lets a principal create, disable and re-enable its own peers within operator-set limits.

**Architecture:**
- **Hub (Go).** The `launcher` peer kind with a 15-minute presence TTL; a 7-day cap on a sender-chosen `expires_at`; a fix so a requester's `cancelled` no longer consumes the recipient's job sequence; issue 28 in full (`POST /v1/peers`, `PATCH /v1/peers/{id}`, principal limits and default scopes, `created_by` in the directory); a kind colour and a principals card in the operator UI; PROTOCOL §18, a §5.6 clarification and the §13.8 launcher checklist. Jobs, threads and approvals otherwise already carry the launcher's wire.
- **Shared hub client (TypeScript).** `connectors/hub-client/` holds the wire types, SSE parser, resumable stream and HTTP client. Its interfaces are a **superset** of the openclaw plan's Tasks 1–4 (`docs/plans/2026-11-01-openclaw-plugin.md`, not built yet): the same `HubApi` (with `putBlob` and `groups`) plus `fetchBlob`, and the same `Clock` plus `timer`. openclaw adopts it by importing this package, switching to `Clock.timer` and reading fakes from `testing/`.
- **Launcher daemon (TypeScript on Node, zero runtime dependencies).** One per host, a pull client with a peer credential. Inbound flow: SSE event → ingress row in a `node:sqlite` ledger → cursor saved and acked → dispatcher → per-session lane → backend plugin. Outbound sends go through a ledger outbox with deterministic idempotency keys, so a crash never loses or doubles a post. Every launcher post in a job thread replies to the launch message, so its loop expiry is the launch's own (see Global Constraints). Backends are plugins behind the design's `Backend` / `SessionHandle` contract; `t3` and `paseo` drive the bridges' existing CLIs, unmodified.

**Tech Stack:** Go 1.26 (`CGO_ENABLED=0`), SQLite migrations, vanilla ES modules in `internal/ui/static/`, Bubble Tea v2. TypeScript run directly by Node's built-in type stripping (Node ≥ 22.18; xsm has 22.23.3, x-tuf 22.22.1, x-tall 24.22.1, x-p35 24.22.0), `node:test`, `node:sqlite`, `fetch`. Dev-only dependencies, exact versions, nothing at runtime: `typescript@7.0.2` (type-check only, the version pag-chat already uses on xsm; it supports `erasableSyntaxOnly`, `allowImportingTsExtensions`, `verbatimModuleSyntax`) and `@types/node` (latest 22.x, for `node:sqlite` and `node:test` types). pnpm 10 installs them.

**Spec:** `docs/design/2026-11-03-launcher.md` (cited as [D]; decisions §10 D1–D9, §10.1 A1–A8, §10.2 D10–D13). `.scratch/vecnet/issues/28-principal-peer-provisioning.md` (frozen with pag-chat, revised 2026-11-03: active-peer cap, `--creates-per-hour`). `.scratch/vecnet/issues/26-agent-sources.md`. ## Global Constraints

### Hub (Tasks 1–5, 20)
- Builds and tests: `build2 go test -p 2 …`, `build2 node --test --test-concurrency=2 …`, `CGO_ENABLED=0 build2 go build -p 2 -o bin/ ./cmd/...`.
- `internal/envelope/schema.json` does not change, and neither do the demo seed (`internal/opseed`) nor any golden file not named in a task. Tests create launcher and principal-created peers at run time.
- Error codes are those of PROTOCOL §15 plus the three issue 28 codes: 403 `kind_not_allowed`, 429 `peer_cap_reached` (`details {limit, active, disabled}`), 429 `peer_create_rate_limited` (`details.retry_after_seconds`, plus `Retry-After` from the existing `writeError`).
- **Issue 28 wire shapes are frozen with pag-chat.** Do not rename a field:
  - `POST /v1/peers {kind, name, idempotency_key}` with a principal credential → `201 {"peer": {"peer_id", "kind", "name", "created_by", "disabled": false}, "idempotency_key"}`. A replay of the same key within 24 h with the same body returns the original response with 200; a different body is 409 `idempotency_conflict` with `details.idempotency_key`.
  - `PATCH /v1/peers/{id} {disabled: true|false}` → `200 {"peer": {…same object, current disabled…}}`. Only for peers the caller created **and** still owns (`created_by` = caller and `prn_id` = caller); any other id is 404 `not_found`.
  - `GET /v1/peers` entries carry `created_by` (a `prn_` id) on principal-created peers; the key is absent on operator-enrolled peers.
- A test marked **(guard)** passes before its task's change and must keep passing; every other listed test fails first.

### Daemon (Tasks 6–18)
- **Location:** `connectors/hub-client/` (shared) and `connectors/launcher/`. `hub-client` has no `package.json` dependencies at all; both are type-checked from `connectors/launcher/tsconfig.json`.
- **TypeScript runs as written.** Erasable syntax only (no `enum`, `namespace`, parameter properties or `import =`); relative imports end in `.ts`; type-only imports use `import type`. `tsconfig.json`: `strict`, `module`/`moduleResolution: "nodenext"`, `target: "es2023"`, `noEmit`, `allowImportingTsExtensions`, `erasableSyntaxOnly`, `verbatimModuleSyntax`, `types: ["node"]`, `include` covering both packages' `src`, `test` and `testing`.
- **Commands:** every build or test goes through a `just ln-*` recipe (Task 6), which runs `build2` with at most 2 workers. Never run `node --test`, `tsc` or `pnpm install` bare. Each worktree runs `just ln-setup` once.
- **No runtime dependencies.** `dependencies` stays empty; `test/boundary.test.ts` (Task 6) enforces it.
- **Plugins** (`src/backends/**`) import only `../../backend.ts`, their own files and `node:*`. Redaction and route checks reach them through `PluginContext.redact` and `PluginContext.checkRoute` (Task 6 contract, wired by Task 17). They never see the hub client, the credential, the hub URL or a raw Delivery. The boundary test enforces this.
- **Authorisation** is keyed only on the authenticated `sender`, plus the hub-set `created_by` from the directory for principal policy keys. Never on names, content, `capabilities` or self-reported tags (PROTOCOL §14.1).
- **Secrets and bodies** never reach logs, thrown messages, job output or presence. The credential is read from a 0600 file; a looser mode refuses to start. Every agent environment passes through `scrubEnv` (Task 8). **All agent-originated text** (turn results, question text, permission summaries, notes quoting the agent, `succeeded.summary`) passes through `redactText` before it is posted.
- **Clock:** every timer goes through the `Clock` port (`hub-client/src/ports.ts`); tests use `fakeClock()`.
- **Loop fields: every launcher post replies to the launch message.** A non-operator reply gets `expires_at = min(parent, now + 24 h)` (`buildLoop`, loop.go:56-92), so a chain of replies-to-replies dies about 24 h after its first link. Replying to the launch message instead gives each post `min(launch expires_at, now + 24 h)`, refreshed on every post, and keeps `depth` at 1. So:
  - turn replies, notes, questions, approval requests and `job_status` all use `in_reply_to` = the launch message (the consumed ids travel in `launch.consumed`);
  - requesters are told (§13.8, Task 19) to reply to the launch message, or to a launcher post less than 24 h old;
  - the session's wall-clock bound is the launch's `expires_at`, which the requester sets on the `job_request` up to the 7-day cap. Without it the hub default is now + 24 h;
  - because depth stays at 1, `max_depth` no longer bounds round trips in a job thread. The bounds are the thread budget (500 messages), per-peer rate limits, the caps and the session deadline.
- **Session lifetime.** `deadlineAt = min(launch loop.expires_at, created + max_session_lifetime)`. The gate refuses a launch whose `deadlineAt − now` is shorter than its effective settle timer plus 10 minutes: `failed {error: "policy_denied", reason: "expires_too_soon", details: {expires_at, needed_ms}}`. At `deadlineAt − 5 min` the idle clock settles the session (`succeeded {ended: "deadline"}`), since nothing can be posted after expiry. An outbox send to a job thread refused 422 `expired` ends the session locally (`failed {error: "expired"}`, recorded in the ledger; the hub post itself cannot land).
- **Ids and keys.** Ids are opaque and copied from the hub. Idempotency keys are pre-assigned per purpose so tasks cannot collide (all match `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`; `<n>` always comes from a ledger counter inside the enqueuing transaction):

| Prefix | Purpose | Owner |
|---|---|---|
| `vl.js.<job_id>.<seq>` | `job_status` (re-sequenced on 409 `stale_sequence`, Task 9) | Task 9 |
| `vl.rc.<delivery_id>.<state>` | receipt | Tasks 11, 12, 17 |
| `vl.tr.<job_id>.<turn_hash>` | turn-result reply (`turn_hash` = first 24 hex of sha256(turn_id)) | Task 11 |
| `vl.nt.<job_id>.<purpose>.<n>` | launcher notes in a job thread | Tasks 11, 12, 17 |
| `vl.ar.<approval_id>` | `approval_request` (the first operator one of a job also opens its escalation thread) | Task 12 |
| `vl.ac.<approval_id>` | `launch.approval_closed` notice | Task 12 |
| `vl.q.<job_id>.<request_hash>` | `launch.question` (`request_hash` = first 24 hex of sha256 of the backend `requestId`) | Task 12 |

- **Outbox semantics** (Task 9; everyone relies on them): 409 `idempotency_conflict` means a key collision bug, so the row is marked `failed` and the key logged, never treated as sent. 409 `stale_sequence` re-sequences the `job_status` from `details.last_sequence`. A `Retry-After` beyond the retry budget holds the row until then without spinning or failing it. Any other 4xx marks it `failed` and calls `onRejected`.
- **Wire conventions** ([D] §3; normative in PROTOCOL §13.8, Task 5):
  - Turn replies: recipients = the thread default; priority = `input.reply_priority` (default `wake_idle`); `metadata` = `{"launch.turn", "launch.turn_id", "launch.job_id", "launch.consumed"}` (at most 100 ids, plus `launch.consumed_truncated: N` when more).
  - `job_status` priority: `hold` for `accepted` and `running`, `wake_idle` for `succeeded`, `failed` and `cancelled`.
  - Permission prompts: `approval_request` to the requester with `metadata["launch.permission"]` v1 ([D] §3.5, closed schema), options = the backend's labels (at most 7, each ≤ 64 chars and unique) plus `escalate` when the route allows it, `escalate_to_operator` from the route, priority `wake`.
  - Escalations and direct-to-operator prompts go into a **per-job escalation thread** with the operator, opened by that job's first operator `approval_request` (`thread_title: "vl escalation: <job title>"`, `metadata["launch.job_id"]`), because a requester-locked job thread refuses a new participant (§16.3 `participants_locked`).
  - Questions: `kind: message` to the requester, priority `wake`, `metadata["launch.question"]` v1.
- **Text limits:**
  - Relayed input per backend send ≤ `min(MAX_TURN_INPUT_BYTES = 96 KiB, caps.maxInputBytes)`; the rest queues as the next input.
  - Inbound spilled text (`content.truncated`) is rehydrated from its spill attachment through `HubApi.fetchBlob` (cap 256 KiB).
  - A turn reply's text is capped at 60 KiB with a `[truncated: N bytes; full text attached]` marker; the full text goes up with `HubApi.putBlob` and rides as a `text/markdown` attachment named `turn-<n>.md`. The hub auto-spills text between 4 KiB and its 64 KiB cap.
- **Attachments** are not passed to agents in P1/P2 (neither backend takes them through its CLI): a relayed message with attachments gets one line `[attachments not forwarded: name (sha256 12), …]`.
- **Ports:** tests listen on port 0. Never use 45752 or 49575.

## Review Focus

1. **Exactly once across crashes.** A redelivered `job_request`, a replay after a cursor reset, and a daemon kill at any point between `accepted` and recording the `SessionRef` each give one session (intent row, `findByTag`, `accepted` resumed). A kill mid-turn posts that turn's reply exactly once (outbox + `turns` row + resumable `turns()` cursor). Backend sends are idempotent (t3 `clientRequestId` from a stored batch id) or at-most-once (paseo). A backend that is unreachable at startup keeps its jobs open and retries; only positive evidence that a session is gone gives `failed {error: "outcome_unknown"}`, and nothing is ever relaunched. Pinned in Tasks 9, 11, 14, 17 and 18.
2. **Who reaches the agent.** Only the requester, the operator and `relay_from` peers are relayed; anyone else gets `processed` with note `not_relayed` and no reply. Controls, question answers and `launch.decision` are accepted only from the senders [D] §3.4–3.6 name. A prompt cannot pick a path (projects are aliases), widen its ceiling or choose its approvers. Pinned in Tasks 10, 11 and 12.
3. **Approvals cannot be spoofed or lost.** Only the addressee (enforced by the hub) or the operator override resolves a prompt. A parent expiry resolves to the backend's deny option, or escalates by config; an operator prompt's expiry always denies, so escalation cannot loop. Escalation keeps the same `launch.permission`. After an override the parent gets `launch.approval_closed`, and a late parent answer gets a superseded note. `launch.permission` validates against its closed schema and stays under 6 KiB. Pinned in Tasks 8 and 12.
4. **Issue 28 cannot widen a principal's power beyond what the operator set.** Default off; `operator`, `source`, `session` and `dot` are never provisionable; the cap counts active peers only, re-enable counts toward it, and `--creates-per-hour` bounds create/disable loops; a principal touches only peers it created and still owns; operator-set default scopes are copied into every created peer, and `principal limits` warns when they are empty while the principal's other peers are scoped; a replay never meets a limit refusal; every refusal is audited. Pinned in Tasks 2 and 3.
5. **Sessions end cleanly.** Park or settle happens only when no turn, approval, question, buffered or native-queued input, or observable background task is open, and no relayed message arrived in the window, except at the hard deadline. Opaque backends use the longer settle timer and say so. A requester's cancel reaches a terminal state at the hub (Task 20). Paseo settle never removes work; workspaces are reclaimed only after retention, clean and with their branch present. Pinned in Tasks 13, 14, 16, 18 and 20.
6. **Bridges stay unmodified, isolated and unclobbered.** The `t3` plugin uses only `t3-bridge` subcommands that exist today, so it neither appends Grok Bot wake instructions nor registers watcher wakes. No task pairs, re-pairs or writes any t3-bridge token or config. The sweep touches only refs whose `extra.tag` starts `vl-`. A failed or ambiguous launch is found by tag and settled at once, so no session runs unsupervised. Pinned in Tasks 14, 15, 16 and 19.

### Task 2: Hub: principal-scoped peer provisioning (issue 28) — storage and logic

**Depends:** none

**Files:**

**Interfaces:**

Stale rows are deleted lazily on lookup, as `idempotencyLookup` does (send.go:693); no ticker change.
- **`provision.go`:**
  - `var NeverProvisionable = map[string]bool{"operator": true, "source": true, "session": true, "dot": true}`. `dot` is added to the issue's list because a dot binds through OAuth link codes, which move it to another principal (`BindDotPrincipalTx`).
  - `const DefaultCreatesPerHour = 60`, `const PeerCreateKeyWindow = 24 * time.Hour`.
  - Types (JSON snake_case): `PrincipalLimits{MaxPeers, CreatesPerHour int; Kinds []string}`, `ProvisionedPeer{PeerID, Kind, Name, CreatedBy string; Disabled bool}`, `CreatePeerRequest{Kind, Name, IdempotencyKey string}`, `CreatePeerResult{Peer ProvisionedPeer `json:"peer"`; IdempotencyKey string `json:"idempotency_key"`; Replayed bool `json:"-"`}`, `PrincipalInfo{PrincipalID, Name string; Limits PrincipalLimits; Active, Disabled, CreatesLastHour, ScopedPeers int; DefaultAllow, DefaultDeny []string}` (slices never nil; `ScopedPeers` = the principal's peers with any `scopes` row).
  - `func (h *Hub) CreatePeer(ctx context.Context, c auth.Caller, req CreatePeerRequest) (*CreatePeerResult, error)`. **Check order**, all inside one `h.DB.Tx`. **Every refusal (steps 1–6) commits one audit row `peer_create_refused` with `{reason: <code>, kind}`** (actor: the caller's principal or peer id; never the body or name) through the `cutError` pattern of `sendAs` (send.go:131-143):
    1. `c.Kind != "principal"` → 403 `forbidden`.
    2. `name` empty or over 128 runes → 422 `invalid_value` `details.field: "name"`; `idempotency_key` off the schema pattern → 422 `invalid_value` field `idempotency_key`; kind not in `PeerKinds` → 422 `invalid_value` field `kind`.
    3. Idempotency on `(c.PrincipalID, key)` with `body_sha256` = sha256 of canonical `{"kind","name"}`: a live row with the same hash → its stored response, `Replayed: true` (not a refusal, no audit); a different hash → 409 `idempotency_conflict`. This runs before every limit, so a retry after a lost response always succeeds.
    4. Kind in `NeverProvisionable` or not in the principal's `kinds` (an absent `principal_limits` row means none) → 403 `kind_not_allowed` with `details.kind`.
    5. Active count `SELECT count(*) FROM peers WHERE prn_id = ? AND created_by = ? AND disabled = 0` ≥ `max_peers` → 429 `peer_cap_reached`, `details {limit, active, disabled}`.
    6. Creates in the last hour, via `windowRetry(ctx, tx, "SELECT enrolled_at FROM peers WHERE created_by = ? AND enrolled_at > ? ORDER BY enrolled_at", prn, creates_per_hour, time.Hour, now)` → 429 `peer_create_rate_limited` with `details.retry_after_seconds`.
    7. Writes: `h.insertPeer(ctx, tx, ids.New(ids.Peer), c.PrincipalID, name, kind, now)`, then `UPDATE peers SET created_by = ?`; copy `principal_default_scopes` rows into `scopes`; store the response in `peer_create_keys`; `h.DirectoryUpdated(ctx, tx, peer, "enrolled", enrolledFields)`; `audit.Record(ctx, tx, c.PrincipalID, "peer_create", [peer, prn], {kind})`.
    - After commit of a create: `h.notifyEnabled(ctx)` and `h.Log.Notify(c.PrincipalID)`, as `AddPeer` does.

- **Outbox:** sends rows in id order and is single-flight.

  - `onSent` lets callers record the `message_id` (questions and approvals need it).

"<state>"`, and `output`. An output over 8 KiB serialised is replaced by `{output_truncated: true, summary: <first 1 KiB>}`.   | { action: "settle"; reason: "idle"; quiescence: "proven" | "assumed" } | { action: "settle"; reason: "deadline" };
```ts
export function idleVerdict(i: IdleInput, now: number, cfg: LauncherConfig["idle"]): IdleVerdict;
export interface IdleClock { track(jobId: string): void; touch(jobId: string): void; untrack(jobId: string): void; stop(): void }
export function createIdleClock(deps: { clock: Clock; log: Log; cfg: LauncherConfig["idle"]; probe(jobId: string): Promise<IdleInput | undefined>;
  park(jobId: string): Promise<void>; settle(jobId: string, why: { reason: "idle"; quiescence: "proven" | "assumed" } | { reason: "deadline" }): Promise<void> }): IdleClock;
```

- **Deadline first:** at or after `deadlineAt − deadline_margin_ms` → `settle` with reason `deadline`, busy or not (the lane interrupts a running turn first; nothing can be posted after expiry).
- **Busy** = a turn running, an open approval or question, a native-queued or launcher-buffered input, or (when observable) a known background task. Busy → `none`.
- Idle since = `max(lastActivityAt, lastRelayAt)`.
- **Park:** after `park_after_ms`, only when `caps.resume === "transcript"`, `canPark`, and the session is `idle`.
- **Settle:**
  - after `settleAfterMs ?? settle_opaque_ms` when background tasks are `opaque` or `none` (quiescence `assumed` for `opaque`, `proven` for `none`);
  - after `settle_observable_ms` for an observable, parked session (`proven`);
  - an observable, unparked session uses the opaque timer, `proven`.
- **Clock:** one timer per job at `min(nextCheckAt, deadlineAt − margin)` (or `check_every_ms`); `touch` re-arms; `probe` returning `undefined` untracks. Park and settle run at most once per verdict. Jobs awaiting reattach (`reattachPending`) are not tracked.

- **Dispatcher**, one ingress row at a time per thread, in parallel across threads. **Every outcome of a row commits in the same ledger tx as `finishIngress`**, so a crash can neither double-post nor post and then decide differently.
  1. **`job_request` with operation `launch`.**
     - `job(jobId)` exists → `done` (a redelivery).
     - `jobByThread(threadId)` exists with a different `job_id` → `failed {error: "unsupported", reason: "one job per thread"}` for the new job.
     - Otherwise `parseLaunchRequest`, `dir.ensureKnown(sender)`, then `gateLaunch`. In one tx with `finishIngress(done)`:
       - a refusal: `createJob` with `state: "ended"` and the refusal as terminal, plus the `failed {error, reason|details}` report;
       - an accept: `createJob` (state `accepted`, `deadlineAt` from the gate), `noteLaunch`, report `accepted {host, backend, preset, permission_mode}`.
     - After the tx, for an accept: create the lane and run `startLaunch`; on success `lane.attach(handle)` and `idle.track`.
  2. **Any other operation** → `failed {error: "unsupported"}`, in the same tx as `finishIngress`.
  3. **`job_status` `cancelled` from the requester** for an open job → `lane.cancel(requester)`. (Since Task 20, the requester's sequence does not touch the launcher's.)
  4. **`approval_response`** → `parentBridge.handleApprovalResponse`.
  5. **A message in a job thread** → `parentBridge.handleThreadReply`. If `unrelated` and it carries `launch.control` → `lane.control(c, sender)`; else `lane.handleMessage`.
  6. **A message in an escalation thread** (`jobByEscalationThread`) that is not an approval response or an operator `launch.decision` reply → `processed` note `not_relayed`.
  7. **Anything else** → `processed` note `not_a_job_thread`.
  - Each row ends `done` or `failed` (an exception: `failed` with the error code, a `failed` receipt, and a log line without a body).
- **Outbox rejections.** `outbox.onRejected` with 422 `expired` on a send in a job thread → `lane.settle("wrapup", "expired")` for that job (session-ending, recorded locally). Other rejections are logged with their tag.
- **Retired requester (F5 backstop).** `directory.onRemoved(peer)` → for each open job of that requester: `lane.control("interrupt", self)`, post a note, and after a 10-minute grace `lane.settle("cancel", "requester_retired")`.
- **Idle wiring:** the idle clock's `probe` builds `IdleInput` from the ledger row, `lane.activity()` and `parentBridge.open()`; its `park` and `settle` call the lane (`settle("wrapup", "idle_wrapup" | "deadline")`).
- **Presence.** Started at boot and re-reported every `heartbeatMs` and on change:
  - state `idle` (no sessions), `working`, `blocked` (at `max_sessions`, or every backend down), `offline` on clean stop;
  - `capabilities` `launch:<backend>`, `preset:<backend>/<preset>`, `host:<host>`, `mode:<m>`;
  - `quota` `{max_sessions, running, open, per_requester, backends}`.
- **Startup order:** load config and credential → `openLedger` → load backends and run health → `directory.refresh` → `reattachAll` (create lanes, attach handles; `unreachable` jobs get lanes without handles) → abandon open parent rows from before the restart → start outbox, idle clock, presence and stream → dispatcher. Timers: `retryPending` every 30 s while any job is pending; hourly `sweep` and `directory.refresh`.
- **`main.ts`:** `run --config PATH` and `check --config PATH`. `check` parses the config, checks the credential mode, loads plugins, prints each backend's health and offered presets as JSON, and exits 1 if any backend is not ok. SIGTERM → `stop()`.
- **`systemd/vecnet-launcher.service`** (a user unit, Max's uid on xsm and, in P2, on the build boxes, D2):
  - `ExecStart=/usr/bin/node --disable-warning=ExperimentalWarning %h/.local/share/vecnet-launcher/current/launcher/src/main.ts run --config %h/.config/vecnet-launcher/config.json`;

## Resolved ambiguities (recorded for Max; each is reversible)

1. **Hub client location.** The openclaw plugin has not been built, so this plan builds `connectors/hub-client/` as a superset of openclaw's Task 1–4 interfaces (same `HubApi` plus `fetchBlob`, same `Clock` plus `timer`); openclaw imports it later.
2. **Tooling.** Node runs the TypeScript directly through type stripping (Node ≥ 22.18, above the design's 22.12; every surveyed host qualifies). Tests use `node:test`, so there is no vitest. Dev deps are `typescript@7.0.2` and `@types/node@22`. No pnpm workspace, so openclaw's own package stays independent.
3. **Config format** is JSON with the design's keys, because a TOML parser would be a runtime dependency. Per-requester caps live only in `policies.*`.
4. **`t3` launch** uses `t3-bridge call t3_thread_launch`, an existing subcommand, rather than `t3-bridge launch`. This sets the `launch/<job_id>` branch and avoids the bridge's Grok Bot wake footer and watcher wakes; since `call` skips the bridge's own selection checks, the plugin validates presets itself. Settle uses `call t3_thread_organize`.
5. **`paseo`** runs in a launcher-made worktree with `--no-worktree`, so the branch is settable and Paseo's settle cannot delete work. Its turns are completion-only (a `wait` reaching `idle`) with best-effort text, because the current CLI has no reliable assistant boundary or stable log cursor.
6. **Escalation** goes to a per-job thread with the operator, opened by that job's first operator `approval_request`, because a requester-locked job thread refuses a new participant.
7. **Reply rule (team lead's decision):** every launcher post replies to the launch message, so the session lives until the launch's `expires_at` (up to 7 d) instead of dying 24 h after the first reply. Depth stays at 1, so loop bounds in a job thread are the budget, rate limits, caps and deadline. Launches whose lifetime cannot cover their settle policy are refused (`expires_too_soon`).
8. **Requester cancel (team lead's decision):** a hub bug, fixed in Task 20; the outbox re-sequences on 409 `stale_sequence` instead of treating it as sent.
9. **`job_status` priorities:** `hold` for accepted and running, `wake_idle` for terminal states.
10. **The `expires_at` cap** also applies to an operator reply's explicit value (it resets the TTL like a fresh message). Peer replies are unchanged.
11. **Issue 28 details:**
    - `dot` joins the never-provisionable kinds.
    - "Own peer" means `created_by` = caller and still `prn_id` = caller.

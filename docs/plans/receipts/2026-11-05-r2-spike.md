## CORS change required before browser acceptance

The coordinator-reported policy permits `content-type`, `content-md5`,
`x-amz-checksum-sha256`, `x-amz-sdk-checksum-algorithm`, `if-none-match`, and
`range`. The planned signed upload additionally sends **`cache-control`,
`content-disposition`, `x-amz-meta-vecnet-checksum-profile`, and
`x-amz-meta-vecnet-checksum`**. An authorized bucket administrator must add these
headers for the intended UI origins. Expose **Content-Range and Accept-Ranges**
as well as the existing ETag, Content-Length and checksum response headers.
Browser JavaScript must not set Content-Length; the browser supplies it from the
fixed Blob. This spike changed no CORS settings.
